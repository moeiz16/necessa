# Security Policy

Necessa is a portfolio-grade reference platform that runs on **synthetic patient data only**.
Do not load real protected health information (PHI) into a deployment unless every service it
uses is covered by a Business Associate Agreement and your compliance team has reviewed it.

## Reporting a vulnerability
Please open a private security advisory on GitHub (Security → Advisories → Report a vulnerability)
instead of a public issue. Include reproduction steps and the affected commit. You can expect
an acknowledgement within 72 hours.

## Built-in controls
- Argon2id password hashing, short-lived JWTs, rotating refresh tokens with reuse detection, TOTP MFA
- CSRF double-submit cookies, strict CORS, security headers, rate limiting (stricter on auth)
- RBAC with tenant isolation enforced in every query (plus Postgres RLS in migrations)
- Field-level encryption (Fernet) for patient demographics and raw clinical text
- Rule-based de-identification before any text reaches an embedding or LLM provider
- Data-class routing: PHI-class calls are refused unless de-identified and routed to allowed groups
- Prompt-injection screening of user input **and** uploaded documents (quarantine on detection)
- SQL generated by models is AST-validated (SELECT-only, allowlisted views, tenant predicate, LIMIT)
- Hash-chained, tamper-evident audit log with an online verification endpoint
- CI: gitleaks secret scanning, Bandit SAST, pip-audit

## Scope notes
- Free LLM tiers generally have no BAA, and some may use submitted content to improve their
  products. That is acceptable here only because all data is synthetic and de-identified first.
- The CMS Medicare Coverage Database is downloaded at runtime and never committed (license terms).
